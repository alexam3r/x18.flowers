# Правила работы над проектом

Этот файл фиксирует обязательные правила для ИИ-агентов и разработчиков,
которые меняют прошивку `x18.flowers`.

## Контекст для продолжения

- **Базовая версия заморожена тегом `v1.0.0`** после проверки на железе.
  HA-конфиг валиден, интеграция Yandex Smart Home успешна.
- Текущий `main` расширяет телеметрию: яркость полок в `status`, MySQL-схема и
  функция Node-RED. Сборка и host-тесты пройдены, проверка нового JSON на
  железе — после перепрошивки.
- [`docs/HANDOFF.md`](docs/HANDOFF.md) — сжатый контекст проекта, архитектура,
  последние решения, ограничения и чек-лист приёмки.
- [`CLAUDE.md`](CLAUDE.md) — краткая точка входа для Claude Code.

## Коммиты

- Сообщение коммита — **на русском языке**.
- В сообщении должно быть понятно, **что сделано в этой итерации**: добавленный
  модуль, изменённое поведение, обновление README.
- Формат: краткая строка-заголовок, при необходимости — тело списком.
- Пример:

  ```
  feat(network): добавлен NetworkManager с динамическим IP брокера

  - Wi-Fi STA, setSleep(false), WIFI_POWER_19_5dBm
  - адрес брокера из WiFi.gatewayIP(), Client ID flowers-esp32
  - watchdog 180 с и телеметрия status
  ```

## README

- Любое изменение прошивки сопровождается правкой [`README.md`](README.md):
  текущий статус, новые модули, топики, особенности реализации, журнал
  изменений.
- README не должен обещать работающий функционал, который ещё не реализован:
  для будущих блоков используйте пометки «Блок 4/5/6» и раздел «Текущий статус».

## Проверки перед коммитом

1. `pio run` — сборка без ошибок.
2. `pio test -e native` — host-тесты (сейчас CIE1931) проходят.
3. Критерии приёмки текущего блока из [`PRD.md`](PRD.md) выполнены.
4. `graphify update .` — граф обновлён.
5. `git status` — в индекс не попали `include/Secrets.h`, `.pio/`, `.pio-core/`,
   локальные бэкапы graphify.

## Порядок работы

- Тег `v1.0.0` — неизменяемый baseline: не переписывать его и не переносить.
- Новые доработки — только по явному запросу пользователя, в отдельной ветке,
  с проверками и проверкой изменений на железе.
- Разработка велась по шести блокам PRD; все блоки реализованы и приняты.
- После изменения: сборка → тесты → graphify → коммит → push → проверка.

## Железо и безопасность

- Пины полок: только `GPIO 0, 1, 3, 4, 10` (полки 1–5 снизу вверх).
- `GPIO 2, 8, 9` — strapping-пины, не использовать.
- ШИМ: 4000 Гц, 12 бит (`0..4095`).
- Реальные Wi-Fi/MQTT-учётные данные — только в `include/Secrets.h`
  (в `.gitignore`). В репозиторий коммитится только `Secrets.h.example`.
- IP MQTT-брокера не хардкодить: только `WiFi.gatewayIP()`.
